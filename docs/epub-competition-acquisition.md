# EPUB 竞品与获客：BizPeel 公开资料研究

核验日期：2026-10-31。研究对象为个人英文 EPUB 书库读者、Kindle 优先的现有产品，不是作者从 Word 出版新书的工具。事实、平台陈述与研究判断在下文分别说明。

## 结论

最直接的竞争来自免费的 EPUB 编辑器和浏览器修复工具。我们需要验证的是：读者能否少做手工操作，并在实际阅读器上看见值得保留的章首、段落层次改善。作者出版软件的收费价格不能证明个人读者愿为美化旧书付费。

BizPeel 对此更适合作为案例线索和分析框架，而非 EPUB 市场规模或付费意愿的证明。本轮公开检索未找到能核验的直接 EPUB 排版报告；这不代表其整个数据库没有相关项目。

## 首轮获客方式

### 自有演示与具体问题页面

先准备同一段文字、相同设备和阅读设置的章首、连续正文、引用三组对照，再解释哪些结构会保留原样。浏览器设计示意、EPUBCheck 和 Kindle 实测分别标注。

一个候选问题页即可，例如 `Clean up chapter openings and paragraph styles in an existing EPUB`。内容先给阅读器设置和 Calibre 的免费处理路径，再说明本产品适用范围。搜索中的 `fix EPUB` 混合编码修复、结构兼容和阅读样式意图；没有搜索量、排名或转化数据时，不把该词当作已验证流量机会。[Calibre 转换指南](https://manual.calibre-ebook.com/conversion.html)、[Google SEO 入门指南](https://developers.google.com/search/docs/fundamentals/seo-starter-guide)。

当前线上仍是旧版试用，英文 PR 尚未部署；全站 noindex 也未改变。不将私有上传、任务、报告或下载链接放入索引。

### 相关社区：先核对规则和证据

- [r/kindle 当前规则](https://www.reddit.com/r/kindle/)禁止产品推广；本轮只用于观察问题，不作为主动推广落点。
- [r/Calibre](https://www.reddit.com/r/Calibre/)贴近个人书库场景，但有推广及题材限制。其[置顶规则](https://www.reddit.com/r/Calibre/comments/1wx55zn/new_sub_rules_aillm_disclosure_and_banning_aillm/)还禁止 AI 写作或润色帖子/评论，并要求项目帖详细披露开发中使用的生成工具。若未来在那里分享，必须由用户本人独立撰写，并满足规则；不能直接粘贴本研究生成的推广文案，人工点击发送也不改变内容的生成方式。
- [MobileRead 总规则](https://www.mobileread.com/forums/faq.php?faq=vb_faq)对推广有专门约束；ePub、Kindle Formats、Reading and Management 的主题匹配不等于可自推。网页服务的具体发布落点仍需重新核验，未核实则不发布。

没有向版主、历史求助者或其他读者发送任何消息；没有发帖、注册账号、批量回复或投放。

## 一个待执行的小实验

假设：已有合法无 DRM EPUB、受章首或段落层次困扰且不愿逐本编辑 CSS 的读者，能从此流程得到可见改善或明显省事。

启动条件：英文版本在 HTTPS 可用；实际 Kindle 对照完成；真实数据说明和反馈入口可用；选定渠道明确允许该分享。用户已选择稍后测 Kindle，所以实验尚未开始。

建议最多招募 10 名目标读者或观察 14 天，先到者为止。可预设“6 人确实下载并打开、4 人能指出具体改善”为第一轮继续条件；这些数字是建议的决策阈值，不是成果或行业标准。实际样本不足时保留分母，不编造成功率。

最小记录：来源 → 查看对照 → 上传 → 处理/保留/失败 → 下载 → 主动报告实机结果 → 是否愿意再处理一本。不收书名、正文或阅读历史作营销画像；同浏览器会话不是稳定的人数。

若多人仍看不出差异，先调整效果和定位；若担心上传或已有工具足够，记录原因。没有价值证据前，不扩大到付费广告、复杂追踪或更多 AI 功能。

## 尚未证实

本轮没有取得直接 EPUB 排版产品的可靠收入、搜索量、获客占比、获客成本或个人读者付费意愿。社区问题只证明存在具体场景，不能推算市场规模。上述优先级和实验设计是研究建议，用户受众定位没有被自动改成作者出版。
